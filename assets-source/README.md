# Tennis asset source contract

Authored sources are organized by tool; GLB is the tool-independent runtime
contract. New low-poly characters and suitable small/medium assets should use
committed `.bbmodel` sources in `blockbench/`, with source exports written to
`blockbench-exports/`. The accepted Phase 04 environment remains sourced from
`blender/TennisPortfolio.blend`, with source exports in `blender-exports/`.

```text
assets-source/
├── blender/                 # accepted Phase 04 sources and legacy/specialized work
├── blender-exports/         # Phase 04 source GLB exports
├── blockbench/              # preferred new .bbmodel authored sources
├── blockbench-exports/      # new source GLB/glTF exports
└── fixtures/                # deterministic pipeline/loader fixtures
```

The Blockbench directories are created when the first authored asset is approved;
do not add placeholder art merely to populate them. Production derivatives belong
in `public/models/`. Never hand-edit source exports or production derivatives.
Do not move, delete, or regenerate the Phase 04 assets as part of the authoring-tool
migration.

## Names and partitions

| Source export | Runtime path | Required stable node prefixes |
| --- | --- | --- |
| `blender-exports/court.glb` | `/models/court.glb` | `ENV_Court_`, `ENV_Net_`, `LINE_` |
| `blender-exports/stadium-shell.glb` | `/models/stadium-shell.glb` | `ENV_Stadium_` |
| `blender-exports/props.glb` | `/models/props.glb` | `ENV_UmpireChair_`, `ENV_Benches_` |
| `blender-exports/scoreboard.glb` | `/models/scoreboard.glb` | `ENV_Scoreboard_` |

`CHAR_`, `PROP_`, `LIGHT_`, and `CAMERA_` names are reserved for later authored
exports. Runtime code must not depend on Blender's autogenerated object names.

## Shared coordinate and export contract

- Export standard Y-up glTF/GLB. Blender sources use meters and Z-up before glTF
  conversion; Blockbench scenes must export to the same application-space scale
  and orientation.
- Court center is application `[0, 0, 0]`; the court is 8.2m × 12.4m outer edge.
- The net runs along X at `z = 0`; north is positive Z.
- Moving character root bones are on the ground plane before export;
  tennis-ball origin is geometric center; racket origin is hand-grip attachment.
- Apply safe transforms, preserve stable authored names, and exclude cameras/lights
  unless deliberately exported. Runtime code must not depend on tool-generated names.

## New Blockbench authoring contract

- Keep the editable `.bbmodel` as the source of truth and commit it according to
  repository asset policy.
- Use stable `CHAR_`, `PROP_`, bone, animation-clip, and socket names. Document any
  runtime-consumed names before integration.
- Prefer one skeleton, a small number of meshes/material slots, and the geometry
  and texture budgets in `docs/RETRO_ART_DIRECTION.md`.
- Place the character root on the ground plane and the racket socket/origin at the
  grip. Confirm scale, handedness, and animation orientation in the application.
- Export a source GLB/glTF to `blockbench-exports/`, then pass it through the
  repository optimization and validation path before copying any production GLB.
- Manually compare the source export and optimized derivative at the authored
  application camera distance. Do not claim an export or visual review occurred
  unless it was actually performed.

## Legacy Phase 04 Blender procedure

1. With Blender installed, run `blender --background --python
   assets-source/blender/create_tennis_portfolio.py`. This creates
   `TennisPortfolio.blend`, every Phase 04 root collection, and the four source
   exports under `blender-exports/`.
2. Build/import each partition with the exact stable object names above. Apply
   rotation and scale to static meshes; keep intentional prop pivots.
3. Export a calibration `court.glb` first. In the browser, it must overlay the
   primitive 8.2m × 12.4m court centered at origin with its net at `z = 0`.
4. Export only the named collection to its matching source path. Preserve mesh
   names; omit unused cameras, lights, and animation tracks.
5. Run `pnpm assets:build`. Compare the exported result at expected camera
   distance before introducing KTX2 textures.

This procedure remains supported for the accepted Phase 04 environment and
legacy/specialized work. Blender is not a prerequisite for ordinary new retro
character authoring.

`fixtures/calibration-glb/` contains deterministic low-poly test fixtures generated
by `scripts/generate-source-assets.mjs`. They exercise the runtime loader and
coordinate contract only; they are not production art. Run `pnpm assets:fixtures`
only to test the fallback path. The checked-in `/public/models` files currently
derive from `blender-exports/`; verify `sourceKind: "blender-export"` in the
manifest after running `pnpm assets:build`.

## Budgets and compression

Each current Phase 04 environment partition is capped at 100KB, except
`scoreboard.glb` at 60KB.
`pnpm assets:build` runs glTF Transform inspect → prune → dedup → weld → high-level
Meshopt compression, preserving stable node names and validated application-space
bounds. Drei's `useGLTF(..., false, true)` enables the compatible Meshopt decoder
at runtime. There are no texture maps in this set, so KTX2/Basis remains disabled
until authored textures can be visually reviewed.

New character budgets are defined in `docs/RETRO_ART_DIRECTION.md`; an asset must
receive an explicit production byte budget when it is added to the optimizer and
manifest. Optimization must preserve skins, animation clips, pivots, sockets, and
stable names.

## Runtime loading and failure contract

The court loads first and retains the primitive court as both its Suspense and
error fallback. Props load only after the court resolves or fails, scoreboard only
after props resolves/fails, and stadium last. Each decorative partition has an
independent error boundary with a null fallback, so a failed decorative request
cannot remove the initial interaction or block later partitions.
