# Tennis asset source contract

The authored source of truth is the `assets-source/blender/TennisPortfolio.blend`
file created by the Blender script. Its exports go to
`assets-source/blender-exports/`, and production derivatives are written to
`public/models/`; never hand-edit either exported derivative.

## Names and partitions

| Source export | Runtime path | Required stable node prefixes |
| --- | --- | --- |
| `blender-exports/court.glb` | `/models/court.glb` | `ENV_Court_`, `ENV_Net_`, `LINE_` |
| `blender-exports/stadium-shell.glb` | `/models/stadium-shell.glb` | `ENV_Stadium_` |
| `blender-exports/props.glb` | `/models/props.glb` | `ENV_UmpireChair_`, `ENV_Benches_` |
| `blender-exports/scoreboard.glb` | `/models/scoreboard.glb` | `ENV_Scoreboard_` |

`CHAR_`, `PROP_`, `LIGHT_`, and `CAMERA_` names are reserved for later authored
exports. Runtime code must not depend on Blender's autogenerated object names.

## Coordinate and Blender export contract

- Use meters, Z-up in Blender; export standard Y-up glTF.
- Court center is application `[0, 0, 0]`; the court is 8.2m × 12.4m outer edge.
- The net runs along X at `z = 0`; north is positive Z.
- Moving character root bones are on ground (`z = 0` in Blender before export);
  tennis-ball origin is geometric center; racket origin is hand-grip attachment.
- Apply safe object transforms, preserve object names, and exclude cameras/lights
  unless deliberately exported.

## Manual Blender procedure

1. With Blender installed, run `blender --background --python
   assets-source/blender/create_tennis_portfolio.py`. This creates
   `TennisPortfolio.blend`, every Phase 04 root collection, and the four source
   exports under `blender-exports/`.
2. Build/import each partition with the exact stable object names above. Apply
   rotation and scale to static meshes; keep intentional prop pivots.
3. Export a calibration `court.glb` first. In the browser, it must overlay the
   primitive 8.2m × 12.4m court centered at origin with its net at `z = 0`.
4. Export only the named collection to its matching source path. Preserve mesh
   names; omit unused cameras, lights, and animation tracks.
5. Run `pnpm assets:build`. Compare the exported result at expected camera
   distance before introducing KTX2 textures.

`fixtures/calibration-glb/` contains deterministic low-poly test fixtures generated
by `scripts/generate-source-assets.mjs`. They exercise the runtime loader and
coordinate contract only; they are not production art. Run `pnpm assets:fixtures`
only to test the fallback path. The checked-in `/public/models` files currently
derive from `blender-exports/`; verify `sourceKind: "blender-export"` in the
manifest after running `pnpm assets:build`.

## Budgets and compression

Each current partition is capped at 100KB, except `scoreboard.glb` at 60KB.
`pnpm assets:build` runs glTF Transform inspect → prune → dedup → weld → high-level
Meshopt compression, preserving stable node names and validated application-space
bounds. Drei's `useGLTF(..., false, true)` enables the compatible Meshopt decoder
at runtime. There are no texture maps in this set, so KTX2/Basis remains disabled
until authored textures can be visually reviewed.

## Runtime loading and failure contract

The court loads first and retains the primitive court as both its Suspense and
error fallback. Props load only after the court resolves or fails, scoreboard only
after props resolves/fails, and stadium last. Each decorative partition has an
independent error boundary with a null fallback, so a failed decorative request
cannot remove the initial interaction or block later partitions.
